1. System map & data flow

Dexcom G7 →(Bluetooth)→ CGM app (xDrip+ or Juggluco) →(local broadcast)→ AAPS →(Bluetooth)→ Omnipod DASH pod

  • All local Bluetooth. No internet is needed to loop. Cell/wifi are not part of dosing.
  • Sensor → CGM app → AAPS every ~5 min → pump. Break any link and the loop pauses (the pod keeps running default basal — see §10).

2. Your eternal build — what's different

Self-signed AAPS 3.4.2.6 (code tag 6c7c) with three stock kill-switches removed:

  • No version expiry — never forces open-loop with age.
  • Objectives neutralized — closed loop/SMB always available.
  • Clock-reset safe — a wrong clock can't wipe progress or disable the loop.
Updating later: rebuild from the same branch and sign with the same aaps-eternal.jks. Same key = installs over the top, no wipe. Different key = uninstall required (data loss). The keystore + passwords are the one irreplaceable thing — keep them backed up (password manager + offline).

3. What each app does

  • AAPS — the brain. Reads glucose, predicts, adjusts basal + gives small corrections (SMB), commands the pump.
  • xDrip+ — primary CGM reader. Native G7; can start a sensor offline with no Dexcom account. Broadcasts glucose to AAPS.
  • Juggluco — backup CGM reader (independent). Same broadcast channel to AAPS. Idle unless xDrip+ fails.

4. Connect & integrate

AAPS core

  1. ☰ → select the AAPS directory (Internal storage/AAPS) if prompted.
  2. Maintenance → Import settings (file in AAPS/preferences) → master password.
  3. Activate profile: ACT → Profile switch → 100% → OK (needs a live pod to fully take — see §10/§11).
  4. Config Builder → BG Source → xDrip+; Pump → Omnipod DASH.
  5. Loop plugin → enable Closed loop.

xDrip+

  1. Settings → Hardware Data Source → Dexcom G7/ONE+.
  2. Settings → Inter-app settings → Broadcast locally: ON (Accept Glucose: OFF).
  3. App battery → Unrestricted.

Juggluco (backup — leave idle)

  1. ☰ → Settings → enable xDrip broadcast (NOT Patched Libre); receiver info.nightscout.androidaps; save.
  2. ☰ → Photo → scan the G7 applicator data-matrix (only when switching to it).
One CGM reader at a time. xDrip+ and Juggluco share the same broadcast into AAPS. Running both = erratic BG, and the G7 only feeds one app. Keep Juggluco's broadcast OFF unless you're switching to it.

5. Move the loop to a spare phone

  1. Spare already has eternal AAPS + your settings. Confirm profile values.
  2. Set BG Source = xDrip+ / Pump = DASH.
  3. Activate a NEW pod on the spare — a running pod is bound to the phone that activated it and cannot transfer. (Keep the PDM as the ultimate backup — see §14.)
  4. Pair the G7 to the spare's xDrip+ (the sensor can only feed one phone; stop the old phone reading it).
  5. Activate profile, close loop.

6. Start a new pod / new sensor

New DASH pod

  • DASH tab → POD MGMT → Activate Pod. Fill with ≥80 U (priming uses ~3–10 U). Two beeps = ready to prime.
  • If "Could not find an available pod for activation" appears — don't panic, tap Retry; it usually continues.
  • Pod life = 72 h + 8 h grace = 80 h. Deactivation is final — a pod can't be reused.
  • Export settings right after every activation (the pod's active state lives in the settings file — a later restore of an older export would drop the new pod).

New G7 sensor

  • xDrip+ (offline-capable): G7 mode selected → insert sensor → it pairs and warms up (~30 min). No account/internet needed.
  • Juggluco: ☰ → Photo → scan the applicator data-matrix; agree to pair within 5 min (keep screen on).
  • Store old sensors ≥15 m away so BT doesn't grab the wrong one.

7. Troubleshooting — loop not dosing

Red "NO PROFILE SET"

Activate a profile (ACT → Profile switch → 100% → OK). If it won't clear and shows "Failed to update basal profile / connection timed out" — AAPS is trying to push basal to a pump that isn't connected. Normal with no pod; it clears once a live pod is paired.

Loop greyed out / not closing

Check in order: profile active? pump connected? BG flowing (not stale >~12 min)? Loop plugin set to Closed? (Objectives are NOT a blocker on the eternal build.) A stale/missing BG stops dosing until readings resume — fix the CGM (§8).

Loop runs but gives little/no insulin

Usually a constraint doing its job: max IOB / max basal / max bolus reached, or a low temp-target/override active. Check the loop reason on the home screen. This is safety, not a fault.

8. Troubleshooting — no / bad glucose

No readings after starting a sensor

Wait out warmup (~30 min). Bluetooth on? Sensor still paired to another app/phone? (one-reader rule). First Juggluco reading can take 2–10 min.

Readings in the CGM app but not in AAPS

xDrip+ "Broadcast locally" is OFF, or AAPS BG source is wrong. Turn broadcast ON and set AAPS BG Source = xDrip+. (For Juggluco: xDrip broadcast ON, receiver info.nightscout.androidaps.)

Erratic / jumping BG

Both xDrip+ and Juggluco are broadcasting. Turn one off — one reader at a time.

Signal loss / gaps

Keep phone within range; body between sensor and phone blocks BLE. Restart Bluetooth (§9). G7 disconnects briefly after each reading — normal.

Switch to the backup reader (Juggluco)

Turn xDrip+ broadcast OFF and stop it holding the sensor → enable Juggluco (xDrip broadcast + info.nightscout.androidaps) → ☰ → Photo → scan the applicator. AAPS BG source stays xDrip+.

9. Troubleshooting — Bluetooth (most off-grid failures)

#1 cause of "pod won't activate" / random pod failures: another app holding the "Nearby devices" permission. Community-confirmed culprits include BM2 solar-battery monitor (very likely in an off-grid/solar kit!), myBMW/MINI, Amazon Alexa, Android Auto. Fix: Android Settings → Security & privacy → Privacy controls → Permission manager → Nearby devices → set every app except AAPS to "Don't allow." Re-check after installing any new app on a loop phone.

status=133 / "Bluetooth device not found" / pod or sensor won't connect

Restart Bluetooth (toggle off/on); if no luck, reboot the phone; disconnect interfering BT devices (earbuds, watch, car); rescan the sensor / retry the pod. In Android Settings → Connected devices, "Forget" a stuck device, then re-pair.

Battery optimization killing the connection

Set Unrestricted battery for AAPS, xDrip+/Juggluco, AND the system Bluetooth app (Settings → Apps → show system apps → Bluetooth → Battery → Unrestricted/Not optimized).

Frequent BT drops on Android 15

Enable AAPS → Preferences → (Advanced) → Bond BT device on Android 15+, accept the pairing request, reboot. Do NOT enable bonding on Android 16.

10. Troubleshooting — pump / DASH

Reassurance: the pod keeps delivering when disconnected. It runs your profile's default basal; AAPS's temp adjustments last max 120 min, then it falls back to default basal automatically. A lost connection is not immediate danger.

"Connecting…" forever

No active pod (expected on a pod-less test phone), or pod out of range (5–10 m) / dead. Move closer; check §9 Bluetooth; on a real pod, Refresh from the DASH tab.

Pod beeping / about to expire

DASH tab → Refresh to silence alerts. Pod life 80 h total. Plan a change before expiry.

Delivery suspended after a profile change and won't restart

DASH suspends delivery before setting a new basal profile; a comms error can leave it suspended. Resume via the DASH tab (Refresh / resume). Watch for it after every profile switch on a live pod.

Basal looks rounded / can't set tiny rates

DASH only does 0.05 U/h steps and has no zero-basal (AAPS uses "Disconnect pump" for true zero). No 30-minute basal boundaries. Not a fault.

Pod failed — start over

POD MGMT → Deactivate (final) → Activate a new pod (§6). Keep ≥80 U per fill. Export settings after activating.

11. Troubleshooting — profile / settings

"Import settings" shows no files

The export must be in Internal storage/AAPS/preferences/, and AAPS must have that folder selected as its directory (☰ → select AAPS directory).

"Basal not aligned to hours" / profile won't save

DASH doesn't allow 30-minute basal boundaries — set basal segments on the hour.

"Data from different pump"

The imported settings carry another pod's activation. Deactivate/activate a pod fresh, or restore the correct export. Always export after each activation.

Values look wrong after import

The imported profile may be an older snapshot. Verify every basal/ISF/carb-ratio/target/DIA against your current settings card before trusting it. Tune in Local Profile, then re-activate.

12. Troubleshooting — phone / Android

Apps keep getting killed / stop updating in background (Samsung)

Battery → Unrestricted for AAPS, xDrip+/Juggluco, Bluetooth; turn Adaptive battery off. This is the most common Samsung failure.

"Nearby devices" permission prompts / pod issues after adding an app

Revoke Nearby devices for the new app (§9). On a loop phone, keep that permission to AAPS only.

Play Protect warns the app is "unsafe"

Normal for a self-built app. More details → Install anyway.

Clock/date wrong after storage

The eternal build tolerates it (loop still runs), but set the clock correctly for accurate history and pod timing. Pods/sensors care about time even when the loop doesn't.

Storage full

Clear space (old logs/exports); AAPS needs room to write its DB and exports.

13. Troubleshooting — reinstall with NO internet

This is why every APK is archived on the phone + the kit USB. Off-grid you cannot re-download — install from the local copies.

Reinstall any app (AAPS / xDrip+ / Juggluco)

Open the archived APK from storage → allow "install unknown apps" → Install. For AAPS, use the copy signed with YOUR keystore.

"App not installed" when reinstalling/updating AAPS

Signature mismatch — the existing app was signed with a different key. Uninstall it first (wipes its data — you have the settings export), then install your signed APK. Always use the same keystore to avoid this.

Restore settings after a reinstall

Open AAPS → select AAPS directory → Maintenance → Import settings → newest export in AAPS/preferences → master password. Verify profile values.

14. Total-failure escalation (decision tree)

  1. Fix in place — work the relevant section above (Bluetooth, CGM, pod).
  2. Swap CGM reader — xDrip+ ⇄ Juggluco (§8).
  3. Swap phone — move to a spare (§5); activate a new pod there.
  4. Fall back to the Omnipod PDM — the standalone controller you kept. Use it to run the pod manually if AAPS/phones are all down.
  5. MDI (Layer 0) — pens + your printed settings card (basal→long-acting, ISF/carb-ratio for corrections/meals). The floor that always works.
Never throw away the PDM — it's the pump's own backup controller for when every phone/app is dead.

16. Cold storage & maintenance

  • Store bagged spares at ~50% charge; top up every ~3 months (reminder).
  • On retrieval: set the clock; confirm profile; the eternal build won't have expired.
  • Re-export settings + reprint the settings card whenever therapy changes; refresh the bagged phones.
  • Verify the keystore backup still exists.

17. Glossary

  • AAPS looping app · CGM glucose monitor (G7 + reader app) · PDM Omnipod's own controller
  • Basal background insulin · Bolus meal/correction dose · SMB small auto correction
  • IOB/COB insulin/carbs still active · ISF drop per unit · ICR/carb ratio g per unit · DIA insulin duration
  • Closed/Open loop auto vs suggest-only · LGS low-glucose suspend
